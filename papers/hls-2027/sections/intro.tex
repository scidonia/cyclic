\section{Introduction}
\label{sec:intro}

Supercompilation~\cite{turchin-1986-supercompiler} fuses composed functions,
eliminates intermediate data structures, and discovers recursive structure
automatically.  Despite decades of development, its proof-theoretic status
has remained informal --- generalisation ``corresponds to lemma introduction''
and folding ``corresponds to induction'', but without the precision to guide
design.

Our starting point is an earlier mechanised result: standard supercompilation
is focused cyclic sequent proof search (companion paper, under review).  The sequent
calculus reveals \emph{what} each SC operation is in proof-theoretic terms:
driving is cut elimination, generalisation is cut introduction, the trace
condition is the global progress check.  This paper shows that the
precise correspondence is more than a correctness proof --- it is a
\emph{design instrument} that identified three gaps in the standard theory
and pointed directly to their solutions.

\paragraph{Gap 1: Generalisation is cut introduction.}
Syntactic anti-unification is a heuristic for cut introduction, but it is
purely structural and cannot discover semantic identities (map fusion,
accumulator introduction).  The sequent formulation immediately suggests
an \emph{oracle architecture}: any function that proposes cut formulas is
valid if the kernel accepts the resulting proof graph.  We instantiate
this with an LLM (DeepSeek V4 Pro); the oracle is untrusted for soundness.

\paragraph{Gap 2: Strengthened induction is the $\omega$-rule.}
Correctness properties like $\mathsf{sorted}\ (\mathsf{sort}\ l) = \mathsf{true}$
require auxiliary lemmas that neither driving nor cyclic induction can discover
alone.  The sequent formulation identifies this as the $\omega$-rule:
prove a lemma first, then use it as a rewrite rule.  We extend the LLM
oracle to propose auxiliary lemmas, validated by a sub-SC run before the
main proof uses them.

\paragraph{Gap 3: Dependent types need type-index reasoning.}
Standard SC treats all types as simply-typed.  In a dependently-typed calculus,
type annotations carry structural information that the SC can exploit.
We implement branch elimination guided by type indices (e.g., pruning
\texttt{vnil} from $\mathsf{Vec}\ (\mathsf{succ}\ n)$), and a type-index
trace condition that recognises recursion on type-level measures as
well-founded.  This enables equalities that standard SC cannot prove:
two programs differing only in pruned dead branches produce identical residuals.

\paragraph{Contributions.}
\begin{enumerate}[leftmargin=*]
\item \textbf{LLM oracle for cut introduction} (Section~\ref{sec:llm}).
  A 3-layer generalisation strategy: anti-unification $\to$ LLM
  generalisation $\to$ LLM lemma proposal.  All LLM proposals are
  validated by the kernel (\texttt{trace\_condition\_ok}).  A controlled
  scrambling experiment shows the LLM reasons from function \emph{structure},
  not name recognition.

\item \textbf{Mechanised $\omega$-rule} (Section~\ref{sec:limits}).
  A lemma environment with sub-SC validation: the LLM proposes lemmas,
  the sub-SC proves them, and the main SC uses them as rewrite rules.
  This enables compiler correctness and reverse-append distribution ---
  properties unreachable by standard SC.

\item \textbf{Dependent-type enhancements} (Section~\ref{sec:design}).
  Type-index branch elimination and type-index trace condition.
  The pruning result \texttt{pruning\_enables\_equality} proves two
  programs with different dead branches produce identical residuals ---
  a genuinely new equality enabled by the type system.
\end{enumerate}

\paragraph{Empirical results.}
65 theorems proved by \vmcompute{} with no human induction tactics,
including all List and Maybe monad laws, insertion sort correctness,
compiler soundness, gradual cast safety, and dependent-type branch
elimination.
